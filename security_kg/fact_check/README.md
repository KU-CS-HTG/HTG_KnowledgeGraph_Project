# 사건 사실 확인표

네 사건(레벨인피니트, SK텔레콤, 2026 금융권, 쿠팡)의 핵심 사실을 한 줄씩 담은 표다. Canvas는 공식 문서를 구하지 못해 2026-11-26에 표에서 뺐다.
**이 사실들은 모두 검색 요약에서 정리한 것이고 1차 자료로 확인하지 않았다.** 평가용 정답과 시험 사례의 바탕이 되므로
사람이 1차 자료와 대조해야 한다.

파일: `incident_facts.csv` (엑셀에서 바로 열린다. 한글이 깨지지 않도록 BOM이 붙은 UTF-8)

**1차 자료를 어디서 받아야 하는지는 `primary_sources.md`에 사건별로 정리했다.**

**파일럿에 쓸 문서의 목록**(37건, 이미 읽은 22건과 추가로 모을 15건)은 `pilot_docs.csv`에 있다(운영-D3). 문서 원본이 아니라 메타데이터만 담는다.

## 열

| 열 | 뜻 | 누가 |
| --- | --- | --- |
| `id`, `incident`, `category`, `claim` | 사건, 분류, **확인할 주장** | 미리 채워 둠 |
| `related_question`, `design_impact` | 이 주장이 관련된 질문 번호와 우리 설계(어디에 쓰이는가) | 미리 채워 둠 |
| `our_source_url`, `our_source_type` | **우리가 이 주장을 얻은 곳**(언론, 보안 업체 등). 1차 자료가 아니다 | 미리 채워 둠 |
| `priority` | 높음(설계와 시험에 직접 쓰임), 보통, 낮음 | 미리 채워 둠 |
| `check_where` | 확인하면 좋은 1차 자료의 종류(일반적인 제안이며 주소는 확인하지 않음) | 미리 채워 둠 |
| `official_url` | **확인에 쓴 1차 자료의 주소** | 사람 |
| `result` | `일치`, `일부 일치`, `불일치`, `확인 불가` 중 하나. 비워 두면 미확인 | 사람 |
| `correction` | `일부 일치`나 `불일치`일 때 **1차 자료가 말하는 내용**(우리가 맞다고 생각하는 것이 아니라) | 사람 |
| `checked_by`, `checked_date` | 확인한 사람과 날짜 | 사람 |
| `note` | 근거, 어려웠던 점, 이유(`확인 불가`일 때 필수) | 사람 |

## 채우는 법

1. **`priority`가 `높음`인 21행부터** 시작한다. 설계와 시험 사례에 직접 쓰이는 것들이다.
2. 사건마다 **1차 자료**를 찾는다. 피해 조직의 공식 공지, 정부·규제기관의 발표(조사 결과, 처분 보도자료)가 1차 자료다. 언론 기사와 보안 업체 블로그는 우리가 이미 가진 출처이므로 대조의 기준이 될 수 없다.
3. 각 행의 `claim`이 **1차 자료의 표현과 맞는지** 본다. 특히 단위(명과 건, GB), 날짜의 기준(침입, 탐지, 공지), 확정과 주장의 구분을 주의한다.
4. `result`, `official_url`, `checked_by`, `checked_date`를 채운다. 맞지 않으면 `correction`에 **자료가 말하는 내용**을 적는다.
5. 1차 자료를 찾지 못하면 `확인 불가`로 하고 `note`에 이유를 적는다. 이것도 정직한 결과다.
6. 채운 뒤 점검한다.

```powershell
python security_kg\fact_check.py
```

규칙에 맞지 않는 칸(근거 주소가 없음, 정정 내용이 없음, 값이 목록에 없음 등)을 알려 주고 사건별 진행 상황과 아직 확인하지 않은 `높음` 행을 보여 준다.

## 주의

- **"출처 간 차이"가 있는 행**(L3, C6, K3와 K4)은 어느 쪽이 맞는지가 아니라 **각 출처가 무엇이라고 했는지**를 적는 것이 목적이다. 평가용 정답이 둘 다를 담아야 한다.
- **"없다"는 주장**(L6, F3, C3, K5: CVE나 취약점이 공개되지 않았다)도 확인 대상이다. 1차 자료에 CVE 번호가 있는지 보면 된다.
- S6의 CVE 번호는 데이터로 존재를 확인했지만(`python security_kg\backbone.py cve CVE-2016-5195`) 그 번호가 사건의 취약점을 가리킨다는 연결은 확인하지 못했다.
- S10은 Claude가 ATT&CK 파일로 이미 확인한 행의 예이다.
- 2026년 사건은 검색 결과에만 의존했고 후속 변동을 확인하지 못했다. 날짜와 수치는 발표된 시점을 같이 기록해 두는 것이 좋다.

## 확인이 끝나면

확인된 행(`일치`, 정정한 `일부 일치`·`불일치`)을 바탕으로 **사건별 정답표**(질문 (a) 취약점, (b) 약점·관리 실패, (c) 기법)를 만들 수 있다. 정답표가 있어야 소규모 실행 결과가 맞는지 평가할 수 있다.
