```text
https://attack.mitre.org/ 들어가보니까 정보를 확인하기 불편하게 되어 있던데 이걸로 어떻게 json파일을 깔끔하게 만들어낸 거야?
```

**답변 요약**: 웹사이트를 읽은 것이 아니라 MITRE가 GitHub에 공개한 STIX 2.1 JSON(`enterprise-attack-20.1.json`, 약 55MB)을 받아 변환한 것이라고 설명했다. 객체 구성(기법, 소프트웨어, 그룹, 관계)과 변환 단계(폐기 제외, ID 추출, 관계 풀기)를 설명했고, 설명문 등은 가져오지 않았다고 밝혔다.

## 120. 사용자 입력

```text
CWE가 비어 있는 CVE가 175건 - 내가 채워야 해?
```

**답변 요약**: KEV에서 CWE가 비어 있는 175건을 CVE 레코드와 대조했다. 66건은 CVE 레코드(CISA-ADP 61, CNA 5)로 채울 수 있고 109건은 어디에도 분류가 없어 추측하지 않는다고 답했다. 사용자가 채울 필요는 없다고 했다.

## 121. 사용자 입력

```text
출처를 구분해서 합쳐두면 뭐가 좋은 거야?
```

**답변 요약**: 출처별로 보관하면 값이 다를 때 어느 출처인지 알 수 있고, 신뢰도를 다르게 줄 수 있고, 빈칸의 이유를 구분할 수 있다고 설명했다. KEV 200건 표본 비교에서 약 12%가 출처끼리 어긋남을 보였다.

## 122. 사용자 입력

```text
진행해줘
```

**답변 요약**: `enrich-kev`로 KEV의 CWE를 출처별(kev, cna, adp)로 보관했다. 1,794건 조회, 대표값 출처는 CNA 716, ADP 863, KEV만 107, 없음 109, 출처 간 차이 232건(12.9%)이다. 앞서 푸시한 CSV 내보내기에서 제너레이터가 칸에 찍히는 버그를 발견해 고치고 시험을 추가했다.

## 126. 사용자 입력

```text

```

**답변 요약**: 어디에도 없는 이름은 데이터를 추가할 때만이 아니라 문서 처리 중 흔히 생긴다고 답했다(한국어 표기, 줄임말, 업체 고유 이름, 스냅샷 이후의 새 행위자, AI의 종류 오류). 새 노드로 추가하면 쪼개짐, 잘못 합치기, 뼈대 정보 부재 같은 문제가 생긴다고 설명하고, 표시하고 합치지 않는 정책을 제안했다.
